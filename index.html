Supervised Machine Learning Classification: Enterprise Customer Churn Prediction & Decision Analysis

Prepared for: Chief Data Officer (CDO) & Head of Analytics · Cohort: N = 2,500 Enterprise Accounts
RUBRIC 1.3 · 1 POINT · MAIN OBJECTIVE PARAGRAPH

Section 1A — Main Analytical Objective

The primary objective of this analysis is to construct, validate, and benchmark a rigorous supervised machine learning classification framework capable of predicting binary enterprise customer churn (churn_status = 1 vs. 0) prior to contract renewal, while balancing predictive discrimination (Recall, Precision, F1-Score, ROC-AUC, and PR-AUC) against executive interpretability (Odds Ratios and Permutation Feature Attribution). Rather than relying on a single classifier, we evaluate five distinct algorithm families—Gradient Boosting (GBM), Random Forest, Support Vector Machine (RBF-SVM), L2-Regularized Logistic Regression, and K-Nearest Neighbors (k-NN)—alongside an unconstrained Decision Tree diagnostic to select the optimal production architecture for proactive retention targeting.

RUBRIC 1.1 · 1 POINT · EXECUTIVE KEY INSIGHTS & FINDINGS

Section 1B — Executive Key Insights & Strategic Recommendation

Across the unseen holdout test cohort (n = 500), Gradient Boosting (GBM) emerges as the top-performing production model, achieving the highest overall Test Accuracy (88.8%), F1-Score (0.754), PR-AUC (0.841), and ROC-AUC (0.888), with the lowest probability calibration error (Brier Score = 0.0989). Operating GBM at a cost-optimized probability threshold of τ = 0.20 (or τ = 0.15) captures 82.6% to 86.4% of all true churning accounts and generates an estimated $157,896 in net retained contract value per 500 accounts. We recommend deploying Gradient Boosting as the primary scoring engine, paired with Logistic Regression Odds Ratios and Permutation Importance as a transparent governance layer.

RUBRIC 1.2 · 1 POINT · DATA DESCRIPTION & FEATURE PIPELINE

Section 2 — Data Description, Feature Engineering & Pipeline Usage

The analysis evaluates a structured enterprise subscription cohort of N = 2,500 customer accounts characterized by 12 domain-specific predictor variables (10 continuous/discrete numerical attributes and 2 categorical attributes) and a binary target outcome (churn_status: 660 Churned [26.4%] vs. 1,840 Retained [73.6%]). Accounts on Month-to-Month contracts exhibit a 41.6% churn rate compared to 10.2% on Two-Year contracts.

How Features Are Used in Building, Training, and Interpreting Models: All preprocessing is encapsulated inside a leak-free Scikit-Learn ColumnTransformer pipeline fit strictly on the 80% stratified training partition (n = 2,000) and evaluated on the 20% unseen holdout test partition (n = 500). Continuous variables (tenure_months, monthly_charges_usd, usage_drop_pct, support_tickets_90d, avg_resolution_hours) are standardized via StandardScaler ($\mu=0, \sigma=1$) to stabilize L2 regularization, RBF kernel distances, and k-NN metrics, while categorical variables (contract_type, payment_method) are converted via OneHotEncoder(drop='first'). In interpretation, usage_drop_pct ranks #1 in GBM Permutation Importance ($\Delta\text{ROC-AUC} = +0.159$), while Logistic Regression reveals that a Two-Year contract reduces churn odds by 89.3% ($\text{OR} = 0.107$).

RUBRIC 1.4 · 2 POINTS · MODEL VARIATIONS COMPARISON & BEST MODEL

Section 3 — Comparing Classification Model Variations & Identifying the Champion

We compared five distinct supervised classification families plus an unconstrained tree baseline on the holdout test set: (1) Gradient Boosting (Champion): 88.8% Test Acc, 89.6% Precision, 65.2% Recall, 0.754 F1-Score, 0.888 ROC-AUC, 0.841 PR-AUC; (2) Random Forest (Bagging Challenger): 87.8% Test Acc, 93.8% Precision, 57.6% Recall, 0.714 F1-Score, 0.893 ROC-AUC; (3) RBF Support Vector Machine: 86.8% Test Acc, 85.9% Precision, 59.9% Recall, 0.705 F1-Score, 0.871 ROC-AUC; (4) L2 Logistic Regression (Interpretable Baseline): 83.8% Test Acc, 80.7% Precision, 50.8% Recall, 0.623 F1-Score, 0.866 ROC-AUC; (5) K-Nearest Neighbors (k=15): 80.4% Test Acc, 37.1% Recall, 0.500 F1-Score; and (6) Unpruned Decision Tree (Depth=None): 100.0% Train Acc vs. 81.2% Test Acc (0.753 ROC-AUC), illustrating severe overfitting. Gradient Boosting is identified as the best model because its sequential shallow trees (max_depth=3) capture non-linear interaction thresholds (+13.1 F1 percentage points over Logistic Regression) while maintaining superior recall (+7.6% over Random Forest) and the best probability calibration (Brier = 0.0989).

RUBRIC 1.5 · 1 POINT · POTENTIAL FLAWS & REVISION PLAN

Section 4A — Potential Methodological Flaws & Plan to Revise Using Additional Data/Techniques

Identified Flaws: (1) Cross-Sectional Snapshot Aggregation: Static 90-day features obscure week-over-week velocity in seat deactivations; (2) Omitted Variable Bias: Lack of competitor pricing shock data and unstructured support ticket NLP sentiment; (3) Binary Window Truncation: Treating churn as a binary 0/1 outcome ignores right-censoring and exact time-to-renewal. Actionable Revision Plan: Augment the feature store with longitudinal rolling telemetry slopes (7d/30d/90d usage velocity) and transformer-based NLP sentiment scores from support transcripts; apply SMOTE-Tomek / cost-sensitive loss weighting; and pair the classifier with a Cox Proportional Hazards / Random Survival Forest model to predict exact time-to-churn.

RUBRIC 1.6 · 2 POINTS · MODEL LIMITATIONS & STRATEGIC NEXT STEPS

Section 4B — Model Limitations & Strategic Next Steps for Production

Operational Limitations: (1) Observational churn probabilities measure correlation rather than causal treatment uplift (offering discounts to "sure things" or "lost causes" wastes budget); (2) Ensemble tree models require post-hoc SHAP computation for individual explanations; and (3) Macro pricing changes can induce covariate and concept drift. Recommended Next Steps: (1) Shift production operating threshold from $\tau=0.50$ to cost-optimal $\tau=0.20$ (boosting Recall from 65.2% to 82.6% and saving $157,716 net ACV per 500 accounts); (2) Deploy TreeSHAP reason codes directly into the CRM dashboard for Customer Success Managers; (3) Execute a randomized A/B retention campaign to train a Causal Uplift Model; and (4) Establish automated monthly Population Stability Index ($\text{PSI} > 0.20$) drift monitoring.
